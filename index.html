Stack

What works with what

One stack is not a strategy. We choose the lightest architecture that carries the product safely: a campaign site should not inherit SaaS complexity, and an ERP should not be built like a landing page.

  1. Interface

    • HTML
    • CSS
    • TypeScript
    • React
    • Next.js
    • Swift and SwiftUI

    Plain HTML and CSS for sites, React or Next.js where component state or server rendering earns its place, native Swift for iPhone and iPad. Talks to the application layer over REST.

  2. Application

    • Node.js
    • Python
    • Flask
    • REST APIs
    • Telegram bots

    Services, background jobs and admin tools built around the operational workflow. Reads and writes the data layer, calls external APIs and runs the automation.

  3. Data

    • PostgreSQL
    • SQLite
    • Oracle
    • SQL
    • Cloudflare D1 and R2

    Entities, relationships and business rules modelled first: safe imports, schema matching, record linkage, roles, search and reports, and stock integrity under concurrent updates.

  4. Infrastructure

    • Linux
    • nginx
    • TLS
    • systemd
    • Docker
    • Cloudflare
    • GitHub Actions

    Git-based releases to your own domain, backups, monitoring and written ownership, so the product can be updated and supported after launch.

  5. Integrations

    • LLM APIs
    • webhooks
    • OAuth
    • payments
    • CRM
    • IIIF
    • geodata

    External content, payment providers, CRM and AI services connected through documented interfaces, with attention to formats, time zones and authentication.

Not every project needs every technology. Every project does need a clear reason for what is included, what is left out and how it will be maintained.

ML and AI

Managing ML and AI work

A model is a component with an owner, a budget and a way to be switched off. We run AI and machine-learning work as a controlled lifecycle, not a demo.

  1. 01

    Task and success measure

    What the model must decide or produce, who relies on it, and the one number that says it works: accuracy, time saved, review rate or cost per item.

  2. 02

    Data

    Sources, licensing and privacy settled first. Cleaning, labelling and retrieval pipelines are documented so results can be reproduced.

  3. 03

    Model and provider choice

    Hosted LLM APIs, retrieval, classical ML or edge inference, compared on your own samples for quality, latency and cost, not on a leaderboard.

  4. 04

    Human review and safeguards

    Generated material stays editable and reviewable. Prompts and model versions are pinned, outputs are validated, and every feature has a graceful fallback.

  5. 05

    Monitoring and handover

    Usage, cost and quality analytics, drift checks and a rollback plan, handed over with documentation so your team can run it without us.
